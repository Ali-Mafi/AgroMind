# AgroMind Progress — 2026-08-27

## Session Summary

Today focused on moving AgroMind out of demo behavior and toward a production-ready application where operational information is always truthful.

The main product rule established and applied today is:

- Real data → show the real value.
- Source not connected → show `Not connected`.
- Source connected but no reading → show `No data`.
- Loading → show a loading state.
- Failure → show an unavailable/error state.
- Fake operational data → never show it inside the real app.

Demo/example content is allowed only inside the Landing feature.

## Irrigation Control

### Fake Local Irrigation State Removed

The old `IrrigationControl` component used local React state to simulate irrigation:

```ts
const [isRunning, setIsRunning] = useState(false);
```

That meant the UI could claim irrigation had started even though no real controller existed.

This behavior was removed.

### Device-Ready Controller States

`IrrigationControl` was redesigned to receive real external controller state.

Supported states are:

```text
not-connected
connected
offline
error
```

Remote controls are enabled only when a real connection and real command handlers exist.

### Control Kept in the Irrigation Page

The control component was intentionally kept instead of being deleted so the Automation UI does not need to be rebuilt later.

Current default behavior without hardware:

```text
Controller
→ Not connected

Start Irrigation
→ Disabled

Stop Irrigation
→ Disabled

Duration controls
→ Disabled
```

This allows AgroMind to communicate that Automation is supported without pretending hardware is connected.

## Future Manual and Automatic Irrigation Architecture

The future behavior for manual and automated farms was defined today.

### Manual Irrigation

When the scheduled irrigation time arrives and no compatible controller is connected:

```text
Schedule due
→ Send reminder notification
→ User irrigates manually
```

Example notification:

```text
It's time to irrigate North Farm.
```

### Automatic Irrigation

When a compatible controller is connected:

```text
Schedule due
→ Backend sends irrigation command
→ Controller receives command
→ Controller confirms successful start
→ AgroMind reports irrigation started
```

AgroMind must never report:

```text
Irrigation started
```

until the actual hardware confirms the command.

Planned irrigation events:

```text
schedule_due
irrigation_started
irrigation_failed
irrigation_completed
```

This feature will require backend scheduling and notification infrastructure.

It must not be implemented using fake client-side timers.
