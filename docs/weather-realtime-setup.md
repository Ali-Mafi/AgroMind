# AgroMind Weather — راهنمای نسخهٔ تمام‌صفحه

تاریخ: 2026-09-09

این راهنما نسخهٔ فعلی مخزن را پوشش می‌دهد: WeatherAPI برای گزارش فعلی، پیش‌بینی ترکیبی ده‌روزه، صفحهٔ تمام‌صفحه، refresh و بارش. تغییرات قبلی مزرعه‌ها و تصاویر WebP حفظ شده‌اند.

## اجرا از مخزن

پس از ذخیرهٔ تغییرات محلی خودت، آخرین شاخهٔ `main` را دریافت کن:

```bash
git pull --ff-only
npm run dev
```

اگر وابستگی‌ها هنوز نصب نیستند، ابتدا `npm ci` را اجرا کن. وابستگی جدیدی اضافه نشده است.

کلید WeatherAPI باید در فایل `.env.local` کنار `package.json` باشد، با نام `WEATHERAPI_API_KEY`. کلید را در فایل React یا متغیر `NEXT_PUBLIC_...` قرار نده. پس از تغییر تنظیمات، سرور را دوباره اجرا کن.

مسیر `/weather` را باز کن. نام مکان ثبت‌شده بالای نام مزرعه است؛ اگر مکان متنی خالی باشد مختصات نمایش داده می‌شود. دکمهٔ پایین سمت راست فهرست مکان‌ها را باز می‌کند؛ دکمهٔ افزودن آن `Add farm` است و هر کارت پنل جزئیات خودش را دارد.

برای اجرای روان‌تر و سنجش عملکرد نسخهٔ نهایی، سرور dev را متوقف کن و از نسخهٔ production استفاده کن:

```bash
npm run build
npm run start
```

## امکانات این نسخه

- پس‌زمینهٔ تمام‌صفحه با حالت روز/شب و استفاده از تصاویر فعلی پروژه؛ فضای امن بالای صفحه و پایین آیفون در چیدمان لحاظ شده است.
- باران واضح‌تر با چند عمق، برف و تگرگ و روشن‌شدن ملایم صحنه هنگام وضعیت رعدوبرق. انیمیشن، بازنمایی وضعیت گزارش‌شده است و رصد زندهٔ قطره یا صاعقه نیست.
- دمای اصلی و کارت Now از یک گزارش واحد هستند. پیش‌بینی ساعت جاری برای شبیه‌سازی Now دست‌کاری نمی‌شود.
- پیش‌بینی ساعتی قابل پیمایش و پیش‌بینی ده‌روزه با نوار کمینه/بیشینه؛ در حالت پیش‌فرض سه روز WeatherAPI و هفت روز Open-Meteo، با منبع مشخص زیر نام هر روز.
- هشت کارت اصلی: بارش، باد و تندباد، دما، رطوبت، کمینهٔ شب، نقطهٔ شبنم، روشنایی روز و فشار. پوشش ابر هم در پنل جزئیات قابل انتخاب است. UV و Visibility در چیدمان اصلی قرار نگرفته‌اند.
- نمودارهای ساعتی با انتخاب نقطه از طریق لمس/ماوس و اسلایدر قابل استفاده با کیبورد، انتخاب روز و معیار، و جدول مقادیر دقیق. نقطهٔ شبنم یا هر مقدار ناموجود با صفر جایگزین نمی‌شود.
- نمودار شب از نیمه‌شب عبور می‌کند و ساعت‌های بامداد بعدی را هم در همان شب نشان می‌دهد.
- فهرست مزرعه‌ها و باغ‌ها، تغییر مکان و دسترسی به افزودن مکان. دمای سایر مکان‌ها قبل از دریافت داده جعل یا از مکان فعلی کپی نمی‌شود.
- تازه‌سازی خودکار هر پنج دقیقه در صفحهٔ قابل‌دیدن، تازه‌سازی دستی، نمایش خطای اتصال و سن گزارش، و بازیابی هنگام برگشت اینترنت.

## معنی عدد بارش

عدد بزرگ کارت Precipitation از **مجموع پیش‌بینی‌شدهٔ همان روز محلی** می‌آید. در WeatherAPI این مقدار `forecast.forecastday[].day.totalprecip_mm` است.

برای نمونه، اگر API مجموع روز را `4` و گزارش فعلی را `0.4` بدهد، کارت اصلی `4.0 mm` با عنوان `Today's total forecast` را نشان می‌دهد. مقدار `0.4 mm` جداگانه در جزئیات گزارش فعلی می‌آید. این مثال صرفاً برای توضیح نگاشت فیلدهاست و گزارش واقعی قزوین نیست.

- پیش‌بینی روزانه، بارش اندازه‌گیری‌شده از ابتدای روز نیست. در پنل بارش، مقدار اندازه‌گیری‌شدهٔ روزانه فعلاً `Unavailable` است، چون ایستگاه یا باران‌سنج به این پروژه وصل نیست.
- بازهٔ تجمیع `current.precip_mm` در مستندات WeatherAPI مشخص نشده؛ آن را «بارش ساعتی»، «۱۵ دقیقهٔ قبل» یا «کل امروز» معرفی نمی‌کنیم.
- در Open-Meteo، دورهٔ گزارش فعلی از `interval` دریافت می‌شود؛ زمان ساعتی بارش، انتهای بازهٔ یک ساعت قبل است.
- احتمال باران و برف جداگانه نام‌گذاری می‌شوند. جمع‌کردن این احتمال‌ها یا تبدیل بیشینهٔ آن‌ها به احتمال مشترک انجام نمی‌شود.
- اگر خود سرویس مجموع روزانه را `0.4` بدهد، کد آن را به `4` تبدیل نمی‌کند. اختلاف با یک منبع دیگر نیاز به مقایسهٔ تاریخ، مختصات، بازهٔ زمانی، نوع داده و پاسخ همان سرویس دارد.

## سرویس، زمان و تعداد روزها

منبع گزارش فعلی و Now همچنان WeatherAPI است. روزهایی که `forecast.json` برمی‌گرداند با مجموع بارش و تمام ساعت‌های همان سرویس حفظ می‌شوند. Open-Meteo فقط روزهای بعدی را تا ده روز تقویمی محلی تکمیل می‌کند؛ ساعت‌ها، کمینه/بیشینه، بارش و نمودار هر روز از همان منبع روز می‌آیند. در نبود کلید یا شکست کامل WeatherAPI، دادهٔ هوا به‌صورت یکپارچه از Open-Meteo دریافت می‌شود و منبع مشخص است.

نام منبع روی ردیف روزانه، مقدار انتخاب‌شدهٔ نمودار و جدول جزئیات دیده می‌شود. اگر شب از مرز WeatherAPI و Open-Meteo عبور کند، خط نمودار در مرز دو منبع قطع می‌شود و توضیح آن نمایش داده می‌شود. زمان مطلق ساعتی Open-Meteo از Unix دریافت و در منطقهٔ زمانی مزرعه نمایش داده می‌شود، تا اختلاف ساعت و تغییر ساعت فصلی باعث جابه‌جایی نمودار نشود.

درخواست روزهای تکمیلی حداکثر چهار ثانیه منتظر می‌ماند و روی سرور تا ۳۰ دقیقه cache می‌شود؛ تاریخ محلی جزو کلید cache است. گزارش فعلی cache نمی‌شود. اگر سرویس تکمیلی در دسترس نباشد، روزهای معتبر WeatherAPI باقی می‌مانند و تعداد واقعی روزهای موجود همراه با پیام نشان داده می‌شود.

WeatherAPI طبق مستندات خودش گزارش فعلی را معمولاً هر **۱۰ تا ۱۵ دقیقه** و پیش‌بینی را هر **۴ تا ۶ ساعت** به‌روز می‌کند. بررسی پنج‌دقیقه‌ای برنامه، انتشار گزارش تازه در سرویس را تضمین نمی‌کند. زمان کنار دما، زمان خود گزارش است؛ زمان بررسی برنامه جدا نمایش داده می‌شود.

پیش‌فرض درخواست WeatherAPI سه روز است. اگر پلن حساب از روزهای بیشتری پشتیبانی می‌کند، می‌توانی این متغیر را در همان `.env.local` تنظیم کنی:

```env
WEATHERAPI_FORECAST_DAYS=10
```

این تنظیم پلن حساب را ارتقا نمی‌دهد. مقدار معتبر بین ۱ تا ۱۴ است؛ مقدار نامعتبر به پیش‌فرض ۳ برمی‌گردد. اگر WeatherAPI خودش ده روز کامل بدهد، نیازی به درخواست تکمیلی نیست. رابط حداکثر ده روز موجود را نمایش می‌دهد؛ دادهٔ گم‌شده تولید نمی‌شود. ده‌روزه شدن به‌تنهایی به معنی افزایش دقت یا فعال‌شدن بارش دقیقه‌ای نیست.

این نسخه از WeatherKit اپل استفاده نمی‌کند. شباهت ظاهری و تعاملی، به معنی استفاده از دادهٔ آیفون یا دقت یکسان با آن نیست. انتخاب سرویس بهتر برای قزوین یا مزرعهٔ تو باید با مقایسهٔ هم‌زمان و قابل‌سنجش انجام شود.

## تصاویر و انیمیشن

تصاویر موجود در `public/weather/backgrounds/` استفاده می‌شوند. نگاشت `features/weather/lib/resolve-weather-background.ts` و تصاویر WebP فعلی خود پروژه حفظ شده‌اند. بارگذار جدید ابتدا نسخهٔ WebP نگاشت را امتحان می‌کند و سپس PNG یا نام‌های مرتبط با همان وضعیت را بررسی می‌کند؛ برای باران و طوفان از تصویر هوای صاف به‌عنوان جایگزین استفاده نمی‌کند.

نام‌های متعارف تصاویر:

| وضعیت | روز | شب |
| --- | --- | --- |
| صاف | `clear-day.webp` | `clear-night.webp` |
| کمی ابری | `partly-cloudy-day.webp` | `partly-cloudy-night.webp` |
| ابری | `cloudy-day.webp` | `cloudy-night.webp` |
| بارانی، در صورت داشتن تصویر جدا | `rainy-day.webp` | `rainy-night.webp` |

برای وضعیت‌های بارانی بدون تصویر جدا، تصویر ابری همان روز/شب به همراه انیمیشن استفاده می‌شود. اگر تصویر مربوط موجود نباشد، زمینهٔ رنگی متناسب با وضعیت نمایش داده می‌شود. تصاویر جدیدی تولید نشده‌اند؛ همان هشت تصویر WebP موجود در مخزن استفاده می‌شوند.

برای جلوگیری از بازگشت افت فریم:

- خود عکس زمینه ثابت است و blur متحرک و جداگانه پشت تک‌تک کارت‌ها اجرا نمی‌شود.
- ذرات با Canvas و سه دستهٔ رسم اجرا می‌شوند؛ انیمیشن باعث رندر مجدد React در هر فریم نمی‌شود.
- اندازهٔ بافر Canvas حداکثر حدود ۹۰۰ هزار پیکسل است؛ برای دسکتاپ نسبت به سقف قبلی ۱.۴ میلیون کاهش یافته، ولی تعداد قطره‌های باران شدید حفظ شده و ضخامت قطره‌ها با وضوح بافر تنظیم می‌شود.
- پس‌زمینه و Canvas لایه‌های رندر جدا دارند؛ فضای scrollbar هنگام بازکردن پنل ثابت می‌ماند. کارت‌ها و پیش‌بینی هنگام بازکردن پنل دوباره محاسبه نمی‌شوند.
- ورود و خروج پنل با جابه‌جایی عمودی و محوشدن نرم انجام می‌شود؛ پنل تا پایان خروج باز می‌ماند و سپس فوکوس برمی‌گردد. Reduce Motion این حرکت را غیرفعال می‌کند.
- ذرات هنگام پنهان‌شدن صفحه، خارج‌شدن از دید، بازشدن پنل جزئیات و فعال‌بودن Reduce Motion متوقف می‌شوند.
- دکمهٔ بالای صفحه امکان توقف افکت‌ها را می‌دهد و ترجیح در همین مرورگر ذخیره می‌شود.
- نمودار تعاملی فقط با بازکردن جزئیات بارگذاری می‌شود؛ نمودار کوچک کارت مستقل و سبک است.

## اعتبارسنجی — 2026-09-09

۴۸ آزمون، بررسی lint کل پروژه، TypeScript و production build موفق‌اند. علاوه بر آزمون‌های قبلی، ادغام ۳+۷ روز، خطای سرویس تکمیلی، منبع ساعت/روز/نمودار، مرز نیمه‌شب و تغییر ساعت فصلی، و چرخهٔ ورود/خروج پنل پوشش داده شده‌اند. گزارش این تغییرات در `docs/weather-ten-day-update.md` است.

```bash
npm test
npm run lint
npm run typecheck
npm run build
```

مرورگر: در مرحلهٔ قبل جریان ساخت مزرعه بررسی شد. در این به‌روزرسانی حالت بدون مزرعه، دکمهٔ Add farm، پنل دسکتاپ، بستن با Escape و بازگشت فوکوس بررسی شدند. نمودارها فعلاً با آزمون داده و خروجی رندر بررسی شده‌اند؛ نمودار زنده و FPS دستگاه هدف هنوز تأیید نشده‌اند.

API واقعی: کلید WeatherAPI در این محیط موجود نبود. درخواست واقعی Open-Meteo از مسیر کد دوباره با خطای دسترسی سرویس/شبکه مواجه شد. بنابراین دریافت زندهٔ ترکیبی، دقت محلی و FPS دستگاه واقعی هنوز تأیید نشده‌اند. گزارش جدید در `docs/weather-ten-day-update.md` و گزارش مرحلهٔ قبل در `docs/weather-verification-2026-09-09.md` است.

### تست زندهٔ سرویس با تنظیمات خودت

این فرمان‌ها از آداپتر واقعی پروژه استفاده می‌کنند و فقط با اجرای صریح، درخواست شبکه می‌فرستند. مختصات پیش‌فرض مرکز تقریبی قزوین است؛ برای بررسی مزرعه، مختصات خودش را بده:

```bash
node scripts/check-weather-api.mjs --provider=weatherapi --latitude=36.27 --longitude=50.01
node scripts/check-weather-api.mjs --provider=open-meteo --latitude=36.27 --longitude=50.01
node scripts/check-weather-api.mjs --provider=auto --latitude=36.27 --longitude=50.01
```

تنظیمات از `.env.local` خوانده می‌شوند و کلید چاپ نمی‌شود. حالت `auto` ادغام واقعی دو سرویس را بررسی می‌کند. خروجی شامل منبع تک‌تک روزها، وضعیت تکمیل ده‌روزه، زمان گزارش، سن گزارش و بارش روزانه/فعلی است. موفق‌شدن این بررسی، صحت قرارداد داده را نشان می‌دهد؛ دقت نسبت به باران‌سنج را تضمین نمی‌کند.

### اندازه‌گیری FPS روی دستگاه هدف

نسخهٔ production را اجرا کن، `/weather` را با دادهٔ کامل باز کن، سپس محتوای `scripts/measure-weather-fps.js` را در Console مرورگر اجرا کن. طی ۱۵ ثانیه صفحه را اسکرول کن. خروجی میانگین FPS، زمان فریم p95/p99 و تعداد فریم‌های بیش از ۵۰ میلی‌ثانیه را نشان می‌دهد. یک بار در هوای صاف و یک بار در هوای بارانی اندازه بگیر و با خاموش‌کردن انیمیشن مقایسه کن. اگر تب پنهان شود، نمونه نامعتبر اعلام می‌شود. این ابزار اطلاعاتی به بیرون ارسال نمی‌کند.
